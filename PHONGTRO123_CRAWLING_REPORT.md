## 2. Methodology & Implementation: Phongtro123.com

### 2.1. Architecture & Discovery

#### Platform Architecture & Stack
- **Frontend / Rendering:** Server-Side Rendered (SSR) HTML generated by PHP backend, styled with Bootstrap & custom responsive CSS, delivered via Cloudflare CDN.
- **Listing URL Pattern & Identifier:** Every individual listing URL follows a deterministic slug containing a unique numeric post ID:
  $$\text{URL Pattern: } \texttt{https://phongtro123.com/\{slug\}-pr\{listing\_id\}.html}$$
  - Example: `https://phongtro123.com/cho-thue-phong-tro-ha-noi/cho-thue-phong-tro-cau-giay-pr613385.html` $\rightarrow$ Canonical ID: `phongtro123_613385`.
- **Contact & Phone Extraction Discovery:**
  - Phone numbers are directly embedded inside the HTML in unmasked `href="tel:09xxxxxxxx"` anchor elements (`<a href="tel:0913209940" class="btn-phone">...</a>`) as well as in the text body.
  - Unlike modern mobile apps requiring SMS OTP or authenticated token exchange, Phongtro123 serves raw phone numbers directly in the initial HTML payload, allowing 100% extraction of unencoded contact details.

#### Catalog Structure & Pagination Ceilings
- **The Page 341 Hard Ceiling:**
  - Inspecting `https://phongtro123.com/tinh-thanh/ha-noi?page={N}` revealed that pagination terminates at **page 341** (~6,800 posts total).
  - Querying `page > 341` returns `HTTP 200 OK` with an empty search result container and static sidebar recommendation cards from other provinces.
- **Taxonomy Tree & Multi-Category Expansion:**
  - To bypass the 341-page ceiling and capture specialized accommodation types across all Hanoi districts, the crawler was configured to traverse distinct category trees:
    1. `/tinh-thanh/ha-noi` (Toàn bộ phòng trọ Hà Nội)
    2. `/cho-thue-can-ho-chung-cu-mini-ha-noi` (Chung cư mini / CCMN)
    3. `/tim-nguoi-o-ghep-ha-noi` (Tìm bạn ở ghép sinh viên / người đi làm)
    4. `/cho-thue-can-ho-dich-vu-ha-noi` (Căn hộ dịch vụ / Studio)
    5. `/cho-thue-nha-nguyen-can-ha-noi` (Nhà nguyên căn)

### 2.2. Crawling Method

The ingestion pipeline was designed as an asynchronous, fault-tolerant system composed of 4 key phases:

```
+-----------------------------------------------------------------------------------+
|                        PHONGTRO123 CRAWLING PIPELINE                              |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
                +---------------------------------------------------+
                |            Phase 1: Async URL Harvesting          |
                |   (src/crawl/run.py & scripts/crawl_all.py)       |
                |   - Concurrent aiohttp HTTP Client (10 Workers)   |
                |   - Category seed expansion & pagination parser   |
                |   - Exponential backoff on HTTP 429/503           |
                +-------------------------+-------------------------+
                                          |
                                          v
                +---------------------------------------------------+
                |            Phase 2: Frontier State Engine         |
                |   (data/frontier.db - SQLite DB)                  |
                |   - URL deduplication table (seen_urls)           |
                |   - Crawled timestamp & HTTP status tracking      |
                +-------------------------+-------------------------+
                                          |
                                          v
                +---------------------------------------------------+
                |            Phase 3: Gzip Disk Caching             |
                |   (data/raw/html/phongtro123/{id}.html.gz)        |
                |   - 5,883 compressed HTML raw response files      |
                |   - Zero re-download overhead for re-runs         |
                +-------------------------+-------------------------+
                                          |
                                          v
                +---------------------------------------------------+
                |     Phase 4: Multiprocess Extraction Engine       |
                |   (scripts/export_all.py using 8 CPU Cores)       |
                |   - BeautifulSoup DOM field extraction            |
                |   - Regex utilities & Geopy coordinate engine     |
                +-------------------------+-------------------------+
                                          |
                     +--------------------+--------------------+
                     |                                         |
                     v                                         v
           raw_phongtro123.csv                       raw_phongtro123.json
         (5,021 clean records)                     (5,021 clean records)
```

#### 1. High-Throughput Asynchronous Crawling (`src/crawl/run.py`)
- Deployed `aiohttp` with `asyncio` task pooling configured at `concurrency: 10` and `min_delay_sec: 0.1s`.
- Applied dynamic browser header rotation (`User-Agent`, `Accept-Language: vi-VN,vi;q=0.9`, `Sec-Fetch-Dest: document`) to bypass basic anti-bot heuristics.

#### 2. Persistent SQLite Frontier Database (`data/frontier.db`)
- Every discovered URL is registered in SQLite with `seen_urls(url, crawled_at, status_code, etag)`.
- Guarantees **0 duplicate HTTP requests** and enables immediate crawl resumption without re-fetching previously crawled pages.

#### 3. Compressed Raw HTML Caching Engine
- Raw HTML response bodies are compressed with Gzip and saved to `data/raw/html/phongtro123/{listing_id}.html.gz`.
- Cached **5,883 compressed HTML fixtures** on disk. This decouples the crawling phase from data parsing, allowing instantaneous offline re-parsing, feature engineering, and model training without making network requests.

#### 4. Multiprocess DOM Parsing Engine (`scripts/export_all.py` & `src/parse/phongtro123_parser.py`)
- Utilizes Python `multiprocessing.Pool` across **8 CPU cores** to parse 5,883 HTML fixtures in parallel within ~30 seconds.
- **DOM Selector Mapping:**
  - **`listing_id`**: Extracted via `re.search(r"pr(\d+)\.html")` $\rightarrow$ `phongtro123_{id}`.
  - **`title`**: `h1.page-h1` or `.post-title`.
  - **`price_vnd`**: `.post-attributes .item.price span` $\rightarrow$ parsed into standard VND float (`3.5 triệu` $\rightarrow$ `3500000.0`).
  - **`area_m2`**: `.post-attributes .item.acreage span` $\rightarrow$ parsed into $m^2$ float (`25 m²` $\rightarrow$ `25.0`).
  - **`address_raw`**: `.post-attributes .item.location span`.
  - **`phone_number`**: `a.btn-phone[href^='tel:']` $\rightarrow$ raw unencoded phone string (`0913209940`).
  - **`description`**: `section.section-post-description .section-content`.
  - **`image_urls`**: `.post-images img[src]`, `meta[property="og:image"]`.

## 3. Data Normalization, Feature Engineering & Geocoding Pipeline

Raw rental posts contain free-form Vietnamese text describing utilities, furniture, house types, and location landmarks. [`src/parse/normalizer.py`](file:///Users/macos/Vietnam-Rental-Room/src/parse/normalizer.py) executes a 5-step feature engineering pipeline:

### 3.1. Utility Price Extraction (Regex Engine)
- **`electric_price`**: Matches `điện 4k/số`, `3.8k/kwh`, `Điện giá dân`, `Miễn phí điện`.
- **`water_price`**: Matches `nước 100k/người`, `30k/khối`, `35k/m3`, `Nước giá dân`, `Miễn phí nước`.
- **`wifi_price`**: Matches `wifi 100k/phòng`, `50k/người`, `Miễn phí wifi`, `Free mạng`.
- **`other_utilities_price`**: Matches `DVC`, `Dịch vụ chung`, `150k/người` (vệ sinh, thang máy, rác, máy giặt chung).
- **`parking_fee`**: Matches `gửi xe 100k/xe`, `Miễn phí gửi xe`, `Free để xe`.

### 3.2. District & Ward Geo-Mapping (`district`, `ward`)
- Standardizes district and ward names across 30 Hanoi administrative units (Cầu Giấy, Đống Đa, Thanh Xuân, Ba Đình, Hai Bà Trưng, Nam Từ Liêm, Bắc Từ Liêm, Hà Đông, Hoàng Mai, Tây Hồ, Long Biên, Hoàn Kiếm, etc.).
- Maps 100+ known ward/street names (e.g. `Dịch Vọng Hậu` $\rightarrow$ `Cầu Giấy`, `Triều Khúc` $\rightarrow$ `Thanh Xuân`, `Mỹ Đình` $\rightarrow$ `Nam Từ Liêm`).

### 3.3. Housing Classification (`house_type`)
Standardizes posts into 7 canonical rental categories:
1. `Chung cư mini (CCMN)`
2. `Studio khép kín`
3. `1 Phòng Ngủ (1PN/1N1K)`
4. `2 Phòng Ngủ (2PN/2N1K)`
5. `Gác xép / Duplex`
6. `Nhà nguyên căn`
7. `Phòng trọ WC chung` / `Phòng trọ khép kín`

### 3.4. Boolean Amenity Flags
Extracts 8 binary indicators ($1 / 0$) with contextual negation checking:
- `air_conditioner` (Điều hòa)
- `water_heater` (Nóng lạnh)
- `refrigerator` (Tủ lạnh)
- `washing_machine` (Máy giặt)
- `elevator` (Thang máy)
- `balcony_window` (Ban công / Cửa sổ thoáng)
- `fire_safety` (PCCC / Thang thoát hiểm / Báo khói)
- `pet_allowed` (Cho phép nuôi pet; excludes `cấm chó mèo`, `không nhận pet`)

### 3.5. Geopy & Centroid Geocoding Engine (`latitude`, `longitude`)
- Integrates `geopy.geocoders.Nominatim` with a fallback **Hanoi Administrative Geo-Centroid Database**.
- **Address Resolution Breakdown (5,021 listings):**
  - **74.85% (3,758 listings)**: Have specific house numbers (55.27%) or alley/lane numbers (19.58%), resolving to exact residential coordinates.
  - **25.15% (1,263 listings)**: Have street-level or ward-level locations, resolving to street/ward centroids.
- **Coverage:** **100% non-null `latitude` and `longitude`** across all 5,021 listings.
- **Distance Metrics:** Calculates exact geodesic distance (`geopy.distance.geodesic`) to university hubs (ĐH Quốc Gia, ĐH Bách Khoa, ĐH KTQD, ĐH Y Hà Nội...) and city landmarks (Hồ Hoàn Kiếm, Keangnam 72).
