## 1. Executive Summary

This report documents the reverse engineering, DOM inspection, browser-automation methodology, memory engineering, and data-normalization pipeline developed to collect **publicly visible posts** from Hà Nội rental-housing **Facebook groups** on `web.facebook.com`.

The crawler is **read-only by design** and operates strictly within the boundary of content already visible to the operator's own logged-in account. It never likes, reacts, comments, shares, joins, follows, messages, or modifies any Facebook data, never handles credentials, and halts immediately on any CAPTCHA / checkpoint / block. Automated collection is contrary to Facebook's Terms of Service; the guardrails reduce risk but do not make the activity ToS-compliant. Use is at the operator's discretion for research.

## 2. Methodology & Implementation

### 2.1. Architecture & Discovery

#### Platform architecture & stack
- **Frontend / rendering:** Facebook "**comet**" **Single-Page Application** — a React-driven, virtualized infinite feed with **autogenerated, unstable CSS class names**. Content is not present in the initial HTML payload; it is hydrated and lazily rendered client-side as the operator scrolls. This rules out a simple `aiohttp` + HTML-parse pipeline and mandates a **real, authenticated browser**.
- **Two DOM variants observed and supported:**
  1. **Comet feed (current `www.facebook.com`):** posts are direct children of a `[role="feed"]` container; the post body is marked `data-ad-rendering-role="story_message"`; there is **no `role="article"` wrapper** and **no clean `/posts/<id>` permalink anchor**.
  2. **Legacy article render:** each post is a top-level `div[role="article"]` carrying a `/groups/<id>/posts/<id>` permalink in the timestamp anchor.
- **Post identity discovery:** because comet omits a clean permalink, the numeric post id is recovered, in priority order, from:
  `/groups/<id>/posts/<id>` → `/groups/<id>/permalink/<id>` → `set=pcb.<id>` (comet photo-bundle link) → `story_fbid=<id>` → `multi_permalinks=<id>`.
  The canonical URL is then rebuilt as `https://www.facebook.com/groups/<group>/posts/<id>`.
- **Anti-fragile field strategy:** every important field uses **multiple ordered strategies with first-reliable-wins** and relies on **semantic signals** (roles, `aria-label`s, `data-ad-rendering-role`, anchor href *shape*, relative DOM position) rather than autogenerated class names — the single design rule that keeps the parser resilient to Facebook's frequent markup churn.

#### Authentication model (credential-safe)
- Two authentication paths, both of which **never read, type, store, or log the password**:
  1. **Persistent managed profile** — Playwright launches Chromium/Chrome with a persistent `user-data-dir`; the operator logs in **manually once** and the session cookie persists across runs.
  2. **CDP attach mode (adopted in production)** — the operator launches a real Google Chrome with `--remote-debugging-port=9222 --user-data-dir=…`, logs in manually, and the crawler **attaches over the DevTools Protocol** (`connect_over_cdp`). Facebook keeps a human-launched Chrome session alive far more reliably than a Playwright-*launched* browser, which it frequently invalidates.

### 2.2. Crawling Method

The ingestion pipeline is an incremental, fault-tolerant, **single-tab browser-driven** system. Concerns are isolated so all Facebook-DOM knowledge lives in exactly one module (`parser.py`).

```
+-----------------------------------------------------------------------------------+
|                    FACEBOOK PUBLIC-GROUP CRAWLING PIPELINE                        |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
                +---------------------------------------------------+
                |     Phase 0: Attach to authenticated Chrome       |
```

#### 1. CDP-attached browser control (`src/crawler.py`)
- Attaches to the operator's Chrome over the DevTools Protocol, opens a **fresh tab**, and calls `bring_to_front()` — a required step, because Facebook's virtualized feed **only renders posts in the active tab** (a background tab shows loading skeletons indefinitely). The crawler's own tab is closed on exit to prevent tab accumulation.

#### 2. Render-aware scroll loop
- After navigation the loop **polls** the DOM (`COUNT_POSTS_JS`) until real, non-skeleton posts appear (nudging the scroll to trigger lazy-load), then repeatedly: expands "See more", extracts, dedupes, saves, prunes media, scrolls to the bottom, and waits a randomized **2–5 s human delay**.
- **Stop conditions:** `max_posts` reached · N consecutive scrolls with no new unique posts · any CAPTCHA / checkpoint / account-verification / block signal (logged as `CRAWLER_STOP_REASON` with a clean exit) · renderer crash (progress already persisted).

#### 3. In-page extraction engine (`src/parser.py`)
- All extraction runs **inside the page** via `page.evaluate(EXTRACT_POSTS_JS)`, returning plain structured objects (no OCR, no screenshots). Selector map:
  - **container**: `[role="feed"] > div` (comet) with legacy `div[role="article"]` fallback; loading skeletons (`role="status"`, "Loading…") and nested comment articles are skipped.
  - **text**: `[data-ad-rendering-role="story_message"]` → `[data-ad-preview="message"]` → largest `dir="auto"` block; Unicode/emoji/line breaks preserved.
  - **post_id / post_url**: multi-strategy id recovery (see §2.1); canonical URL rebuilt from the group id/slug.
  - **timestamp_text**: anchor whose text/aria-label is a relative time ("27m", "5 h", "Just now"); author links (`/user/`) excluded; absolute `timestamp` only stored when an ISO `<time datetime>` is present (never guessed).
  - **reaction_count**: `aria-label` containing a digit + reaction/like phrase (e.g. `"Like: 12 people"` → 12).
  - **comment_count / share_count**: accepted **only** when a digit sits next to the localized noun (`<n> comments|bình luận` / `<n> shares|chia sẻ`).
  - **image_urls**: `scontent.*.fbcdn.net` ≥120 px; UI sprites (`rsrc.php`, `static.*.fbcdn`), emoji, stickers, avatars and small icons excluded; deduped.

#### 4. Normalization, dedup & incremental persistence (`src/utils.py`, `src/exporter.py`)
- **`parse_count`** normalizes localized counts: `1.2K→1200`, `2.5M→2500000`, `1,234→1234`, and Vietnamese forms `1,2K→1200`, `2,5Tr→2500000`, `5N→5000`.
- **`normalize_url`** canonicalizes host to `www.facebook.com`, strips tracking query/fragment; **`normalize_text`** preserves Vietnamese Unicode/emoji/line breaks.
- **Deduplication order:** `post_url` → `post_id` → `SHA256(normalized_text + timestamp_text)` fallback — so anonymous posts with no recoverable permalink are still deduplicated.
- **Incremental & restartable:** every new record is appended to `posts.jsonl` and `fsync`-flushed immediately; a checkpoint (`unique_posts`, `last_post_url`, `scroll_attempts`, `stop_reason`) is written every N posts. On restart the crawler rebuilds the known-key set from `posts.jsonl` and continues without re-writing existing data — so a mid-run crash loses **nothing**.

#### 5. Multi-group orchestration (`src/multi.py`)
- Crawls several groups in one invocation, each into an isolated `data/<slug>/` directory (own `posts.jsonl`, `posts.csv`, `checkpoints.json`, `validation_report.md`, log). Duplicate group URLs are crawled once; one group's failure never aborts the others.

## 3. Engineering Challenges & Resolutions

The most substantial engineering effort was **surviving long single-tab crawls** and **adapting to comet's obfuscated DOM**. Each issue below was diagnosed against the live logged-in DOM and resolved in code.

| # | Symptom | Root cause | Resolution |
| :-- | :--- | :--- | :--- |
| 1 | 0 posts extracted; only 2 "articles" found | They were `role="status"` **loading skeletons**; real posts not yet rendered | Poll-until-rendered (`COUNT_POSTS_JS`) with nudge-scroll before extracting |
| 2 | Feed never rendered in CDP mode | New CDP tab opened in the **background**; comet only renders the **active** tab | `page.bring_to_front()` after opening the tab |
| 3 | Re-login required every run | Facebook invalidates a **Playwright-launched** browser's session | **CDP attach** to a human-launched Chrome; persistent `user-data-dir` |
| 4 | `connect_over_cdp` refused on `::1` | `localhost` resolved to IPv6; Chrome debug port is IPv4-only | Auto-retry `localhost → 127.0.0.1` |
| 5 | Attach hung after a crash | Crashed/leaked tabs accumulated (14 targets) and wedged the browser | **Close our own tab each run** (leak fix) + clean Chrome restart |
| 6 | Group 2 had 0 permalinks | URL builder matched only **numeric** group ids; `nhatrohngiare` is a **vanity slug** | Broaden group-id regex to `/groups/([^/?#]+)/`; backfilled 1,056 URLs |
| 7 | Comment/share counts mostly null | Comet renders these as **bare numbers** with no adjacent word | Only accept counts with a digit next to the localized noun; leave null otherwise (never invent) |
| 8 | **Renderer OOM ("Target crashed") at ~1,200 posts** | A single tab accumulates thousands of image-heavy posts until Chrome kills the renderer | See below — the memory wall |

### The ~1,200-post memory wall
Three memory strategies were tested against the live feed:

| Approach | Result |
| :--- | :--- |
| No pruning | Crash at ~1,203 posts |
| Remove old DOM nodes | Bounds memory, **but breaks Facebook's infinite-scroll loader** → stalls at ~200 posts |
| **Blank media of already-saved off-screen posts (keep nodes)** — *adopted* | Scroll loader stays healthy; frees decoded-image memory; extends the run, but a hard ceiling remains |

The adopted `PRUNE_FEED_JS` blanks `<img>`/`<video>` sources of all but the most-recent *N* feed children each cycle (nodes retained so scroll/observers survive). This pushed runs to **~1,155–1,240 posts/group** before the renderer's RAM ceiling on this hardware. Because saving is incremental, hitting the wall costs no data. Exceeding ~1,300/group in one pass would require an **auto-restart segmentation** approach (reload the tab to reset memory, resume via the existing dedup) or more RAM — identified as future work.

## 4. Data Schema

One JSON object per line in `posts.jsonl`; the combined CSV prepends a `group_name` column.

| Field | Meaning |
| :--- | :--- |
| `post_id` | Numeric id recovered from the permalink / photo-bundle, else `null` |
| `post_url` | Canonical permalink (preferred unique identifier) |
| `group_url` | The group being crawled |
| `timestamp_text` | The label Facebook displayed (e.g. `"27m"`, `"5 h"`, `"Just now"`) |
| `timestamp` | Absolute ISO time, only when reliably available; never guessed |
| `text` | Full post text; Vietnamese Unicode / emoji / line breaks preserved |
| `reaction_count` / `comment_count` / `share_count` | Integers, else `null` |
| `image_urls` / `video_urls` | Deduplicated lists of post-media URLs (media not downloaded in v1) |
| `crawl_time` | ISO time the record was collected |

Unavailable values are stored as `null` — never invented. In the combined CSV, `image_urls`/`video_urls` are serialized as JSON strings (UTF-8).
